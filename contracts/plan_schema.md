# Схема Plan

Ответственный: Человек 1 (planning) / Человек 2 (recalculation)

## Plan

| Поле      | Тип                    | Описание                                                                 |
|-----------|--------------------------|---------------------------------------------------------------------|
| baseline  | list[PlannedTask]        | Неизменяемый снимок плана, зафиксированный на Неделе 0                |
| current   | list[PlannedTask]        | Обновляемый список PlannedTask, актуальный план на текущий момент     |

## Правило неизменности baseline

**`baseline` не изменяется при пересчёте плана.** Он формируется один раз функцией
`backend/recalculation/baseline.py::save_baseline` на Неделе 0 и в дальнейшем доступен
только на чтение.

Все KPI (`pi_predictability`, `say_do_ratio`, см. `backend/kpi/metrics.py`)
считаются как сравнение `current` (или факта) против `baseline`, а не против
предыдущей версии `current`.

`current` обновляется функцией `backend/recalculation/recalc.py::apply_sprint_fact`
на каждом спринте, затрагивая только незавершённый хвост плана (Todo/InProgress),
не трогая задачи в статусе Done и не трогая `baseline`.

## Дополнительные поля Plan

| Поле            | Описание                                                              |
|-----------------|-----------------------------------------------------------------------|
| current_sprint  | Последний спринт, по которому внесён факт (0 — Неделя 0)              |
| capacity        | `{"team_sp": {команда: SP}, "engineer_hh": {инженер: ч}}`               |
| history         | Снимки по спринтам: `fact`, `changes`, `alerts`, `resolved_alerts`     |
| alerts / resolved_alerts | Алерты последнего пересчёта (см. `alert_schema.md`)          |
| engineers_unavailable / engineers_hired | Кадровые изменения из фактов                  |

## Правила планировщика (`backend/planning/scheduler.py::build_baseline_plan`)

- Жёсткие ограничения: SP команды в спринте ≤ ёмкости (SP задачи списываются
  пропорционально часам — `sp_by_sprint`); часы инженера ≤ 80 × `capacity_rate` по
  каждой его команде; зависимая задача — не раньше спринта после окончания блокирующей.
- Порядок: топологический; среди доступных — `plan_rank` прошлого плана (при
  пересчёте), задачи в работе, скоринг, rung.
- `missing_roles="partial"` (по умолчанию) — роли без людей в дефицит + частичная цель;
  `"postpone"` — строгий перенос.
- Если задача не поместилась, её часы и SP возвращаются в пул.

## Пересчёт

`recalc.py::plan_tasks` передаёт в планировщик хвост задачи: остаток часов,
остаток SP (без ролей в дефиците), полную смету `estimate_total_hh` и место в прошлой
очереди `plan_rank`. Поэтому без отклонений пересчёт воспроизводит собственный план
(сценарий `on_track`: ноль сдвигов за 6 спринтов).
